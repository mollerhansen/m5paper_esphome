# Enhancing the M5Stack Paper with ESPHome: A Custom Home Assistant Dashboard

**Date:** May 26, 2026  
**Author:** David  
**Project Source:** [M5Paper ESPHome Project](https://github.com/mollerhansen/m5paper_esphome)  
**Original Source:** [sebirdman/m5paper_esphome](https://github.com/sebirdman/m5paper_esphome)

The **M5Stack Paper (M5Paper)** is a unique piece of hardware: a 4.7" e-ink display powered by an ESP32, featuring a GT911 touchscreen, a BM8563 RTC, and built-in environmental sensors. While it's a powerful device, getting it to work seamlessly with Home Assistant requires a bit of custom magic.

In this post, I'll walk through the setup of this project, the custom components involved, and the recent UI improvements I've made to make the device feel more "alive."

---

## The Hardware

The M5Paper is more than just a screen. It includes:
- **4.7" E-Ink Display**: High contrast and low power (960x540).
- **GT911 Capacitive Touchscreen**: Multi-touch support for interaction.
- **SHT30 Sensor**: For local temperature and humidity.
- **BM8563 RTC**: Essential for deep sleep and scheduled wake-ups.
- **Power Management**: Internal battery and controllable power rails.

## The Software: Integrating Custom Components

To unlock the full potential of the M5Paper, this project integrates several powerful custom ESPHome components originally developed by **Stephen Bird ([sebirdman](https://github.com/sebirdman))**:

1.  **`it8951e`**: The driver for the e-ink display controller. It supports partial updates, allowing for faster UI responses without a full screen flash.
2.  **`gt911`**: Handles the touchscreen input, allowing for defined touch regions and buttons directly in the ESPHome YAML.
3.  **`bm8563`**: Manages the Real-Time Clock, which is crucial for low-power operation and precise deep-sleep wakeups.
4.  **`m5paper`**: A board support component that manages the specific power rails (GPIO2 for main power, GPIO5 for battery/peripherals).

My work has focused on taking these robust drivers and building a cohesive, user-friendly system around them—including the UI framework, Home Assistant integration, and specific behavioral refinements.

## Project Structure & Setup

The project is structured to be modular and easy to extend:
- `m5paper.yaml`: The main configuration file defining the pages, sensors, and touch logic.
- `display_helpers.h`: A C++ header containing custom drawing functions (like speech bubbles and sprite rendering).
- `helper_assistant/`: A collection of 2-bit grayscale Pikachu sprites that act as a "Helper Assistant."

### Custom Display Logic
Instead of a static dashboard, I've implemented a "Helper" system. Depending on the state of the house (e.g., CO2 level, door locks, washing machine status), a Pikachu sprite appears with a speech bubble providing a Call to Action (CTA).

## Recent Improvements

Over the last few weeks, I've refined the experience with several targeted updates:

### 1. The Sleeping Pikachu (v2.2)
To make the screen feel less "static" when nothing is happening, I added a sleeping Pikachu that appears at the bottom center when the device is idle. This required careful layout adjustments to ensure it didn't overlap with the "Luft ud" (Ventilate) button and CO2 display.

### 2. Smart Alert Priority
I fixed a bug where less important alerts (like the washing machine finishing) would override critical security alerts (like the basement door being unlocked late at night). I swapped the priority in the Home Assistant logic to ensure security always comes first.

### 3. Sprite Cleaning
During implementation, I noticed a pesky vertical line on the right side of some Pikachu sprites. I tracked this down to trailing black pixels in the grayscale image data and programmatically cleaned the header files to ensure a crisp, artifact-free display.

### 4. Better Power Thresholds
I adjusted the power sensing logic for the washing machine to avoid "phantom" alerts triggered by standby power, ensuring the device only notifies us when a load is truly finished.
